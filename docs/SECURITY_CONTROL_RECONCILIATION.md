# Security Control Reconciliation

Last reconciled: 2026-08-18

This document reconciles the security acceptance items that remain unchecked in `TASK.md` with the current implementation. It is deliberately evidence-based: a control is not treated as complete merely because a similar feature exists.

Status meanings:

- **Implemented** — the control exists in runtime/database code and has a concrete enforcement point.
- **Partially verified** — substantial enforcement exists, but the repository-wide or operational acceptance claim is broader than the evidence reviewed.
- **Not applicable today** — the risky capability is not present; adding it requires the stated control first.
- **Pending** — the requested control is not yet complete.
- **Operational pending** — application support exists, but external operational evidence must be produced outside the source tree.

## Release rule

Before any unchecked `TASK.md` security box is changed to complete, attach one of the following to the control:

1. an implementation path plus automated acceptance-test reference;
2. an explicit **Not applicable** decision with the prohibited/future capability named; or
3. immutable operational evidence for controls that cannot be proven from source code.

The migration validator (`npm run db:check`) remains a required release gate for exposed-table RLS, grants, relation references, and SECURITY DEFINER search-path safety.
