# Security Control Reconciliation

Last reconciled: 2026-08-24

This document reconciles security acceptance items against concrete runtime/database enforcement. A control is not complete merely because a similar feature exists.

Status meanings:

- **Implemented** — the control exists in runtime/database code and has a concrete enforcement point.
- **Not applicable today / guarded** — the risky capability is not present, and a release guard prevents it from being added without the stated boundary.
- **Operational pending** — application automation exists, but external operational evidence must still be produced outside the source tree.

## Input and output controls

| Control                             | Status                                | Evidence / decision                                                                                                                                                                                                                                                                                                                                              |
| ----------------------------------- | ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Schema validation on every mutation | Implemented                           | `scripts/security/check-mutation-boundaries.mjs` inventories server actions and mutation routes through the TypeScript AST. The current inventory covers 267 mutation boundaries: 260 schema-validated, four with no caller input, three narrowly reviewed exceptions, and zero uncovered. `npm run security:mutation-boundaries` is a release gate.             |
| HTML sanitization                   | Implemented for current HTML surfaces | React output encoding remains the default and raw browser HTML injection APIs are prohibited by `scripts/security/check-sensitive-content-boundaries.mjs`. Uploaded HR HTML templates pass the positive element/attribute allowlist and unsafe CSS/URL checks in `src/modules/hr/server/document-template-compiler.ts`; storage routes reuse the same validator. |
| Rich-text allowlist                 | Not applicable today / guarded        | AgencyOS still has no general rich-text editor. The existing HR HTML-template surface uses a positive element/attribute allowlist, and `npm run security:sensitive-content` fails if browser raw-HTML injection APIs are introduced. A future rich-text feature must reuse or extend an allowlist boundary before merge.                                         |

## Backup and recovery controls

| Control         | Status              | Evidence / decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| --------------- | ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Restore testing | Operational pending | AgencyOS now includes `npm run security:restore-drill:verify`, which refuses production mode, requires an explicitly identified isolated restore target/backup set, reuses deployment verification for PostgreSQL + HTTP/DNS/TLS checks, and runs object-storage, scanner, and worker checks. It writes private SHA-256-addressable evidence. This does **not** fabricate proof that backup data was restored: a real production-like PostgreSQL + object-storage + configuration + DNS/TLS + secret-manager restore must still be executed and its provider/operator evidence attached to the immutable Security restore-drill record. |

## Release rule

Before any security checkbox is changed to complete, attach one of:

1. an implementation path plus automated acceptance-test reference;
2. an explicit **Not applicable / guarded** decision naming the prohibited/future capability; or
3. immutable operational evidence for controls that cannot be proven from source code.

Required source-tree gates include `npm run security:mutation-boundaries`, `npm run security:sensitive-content`, and `npm run db:check`.
